# Visory 页面信息架构与低保真原型 v1

状态：MVP UX Baseline

最后更新：2026-08-28

## 1. 设计目标

页面服务于“事实状态清楚、结论有证据、任务可追踪、结果可复现”，不是交易终端仿制。所有数字都必须能回答：什么日期、什么口径、什么快照、质量如何、能否用于正式策略。

前端技术基线沿用`apps/dsa-web`的React、Vite和TypeScript，但用户可见的产品名、页签、登录页和应用Shell统一显示`Visory`。页面通过FastAPI查询已发布资源，不直接读取Parquet、Worker目录或Provider。

## 2. 全局信息架构

```text
登录 P-LOGIN
  └── 平台壳
      ├── 总览 P-DASH
      ├── 市场 P-MARKET
      ├── 板块 P-SECTOR
      ├── 个股 P-STOCK
      ├── 复盘 P-REVIEW
      ├── 研究 P-RESEARCH
      ├── 策略 P-STRATEGY
      ├── 回测 P-BACKTEST
      ├── 数据质量 P-DATA
      ├── 任务运维 P-TASKS
      └── 设置 P-SETTINGS
```

全局搜索支持股票代码/名称、板块、策略、回测Run、Task和报告。搜索结果按资源类型分组；歧义输入展示候选，不自动跳转。

### 3.2 全局组件

| 组件 | 行为 |
| --- | --- |
| `TradeDatePicker` | 只允许交易日；切换后所有页面保留同一日期上下文 |
| `SnapshotBadge` | 显示Provisional/Certified/Partial/Stale/Corrected，点击进入P-DATA |
| `TaskIndicator` | 活跃/失败任务数量，点击进入P-TASKS |
| `EntitySearch` | 调Identity Resolver，歧义展示候选 |
| `EvidenceDrawer` | 展开指标口径、Claim/Evidence、Raw/Feature血缘 |
| `CompareDrawer` | 对比Snapshot/Strategy/Run/Correction版本 |
| `ErrorBoundary` | 展示错误码、Request ID和任务链接，不展示堆栈 |

### 3.3 视觉语义

- 绿色/红色用于涨跌时，质量状态不再只靠红绿，必须配图标和文本；
- `CERTIFIED`、`PROVISIONAL`、`PARTIAL`、`STALE`有固定Badge；
- AI观点使用独立背景和“AI分析”标签，不能与客观事实卡同样呈现；
- 数字至少展示单位、统计窗、口径Tooltip；
- 正式/研究/预览回测使用明显不同标签；
- 所有可点击ID提供复制按钮，默认显示短ID但详情展示完整ID。

### 6.2 Tab要求

| Tab | 组件 | 禁止项 |
| --- | --- | --- |
| 大盘结构 | 指数K线、量价、波动、趋势、关键区间、风险事件 | 不输出AI买卖点 |
| 市场宽度 | 涨跌家数、分位、新高新低、涨跌停、连板生态 | 缺失值不得当0 |
| 情绪 | 五维分量、总分、状态、历史轨迹、定义版本 | 不隐藏分量只给总分 |
| 资金行为 | 多通道证据、可信度、覆盖、来源、历史对比 | 不宣称单一“主力资金真值” |
| 全球背景 | 指数/汇率/利率/商品/事件 | 明示“不参与A股策略和回测” |

## 17. 响应式规则

- ≥1280px：固定侧栏，内容两列/多列；
- 768–1279px：可折叠侧栏，卡片两列，表格允许列管理；
- <768px：底部主要导航+抽屉次导航，卡片单列，表格切换为关键字段列表；
- 图表必须支持触摸Tooltip和横向缩放；
- 移动端保留Snapshot状态、trade_date和Evidence入口，不能为了适配隐藏质量信息；
- 高风险Command在移动端仍需完整确认，不使用单次滑动误触。

## 18. 无障碍与格式

- 所有状态不仅靠颜色；
- 键盘可操作导航、Tab、Drawer和Dialog；
- 图表提供数据表或摘要；
- 中文数字使用明确单位，金额单位可切换但原始值口径固定；
- 时间默认Asia/Shanghai并可查看原始RFC 3339；
- 股票代码显示`canonical_id`或市场标识，避免只显示六码裸码；
- Loading使用骨架屏，长任务使用Task进度，禁止无限Spinner。

## 19. 前端验收

每页必须完成：

1. Desktop和Mobile布局；
2. Loading/Empty/Provisional/Partial/Stale/Error/Success/Corrected状态；
3. 401跳登录、403无权限、409冲突、422契约不满足和503依赖失败；
4. 请求取消、重复点击幂等和页面刷新恢复；
5. Snapshot/Resource ID、日期、质量和Evidence入口；
6. URL可复现筛选条件，敏感数据不进入URL；
7. Playwright关键旅程和视觉快照；
8. API TypeScript类型由OpenAPI/Schema生成，不手写漂移接口。
